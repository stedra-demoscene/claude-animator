# Music

The score is MIDI generated by a script from `events.json`, rendered with a sample library, mixed against the
voice. It lives on **one global clock**, the same one as the picture.

You cannot hear it. You can measure it. The user's ears decide. Give them short renders per scene and ask
specific questions ("does the cello enter where you expected?").

## Defaults (the user may overrule any of these)

- **No ducking.** Music sits at a fixed level under the voice, roughly 10 dB below speech RMS. Layers add
  colour, not loudness.
- **No arpeggios or beat-keeping filler** under narration. Pads, sub, a theme, held countermelodies, swells.
  Rhythm only if the user asks for it ("pata-pata eighth notes" is a valid note from a user, not a default).
- **Silence is an instrument.** A sudden stop after a build should sound like a hall, not a mute button.
- **Fixed palette per film.** Pick it with the user in the first round (3 short sketches of 20 s: for example a slow
  pad, a plucked pulse, a plain piano). Extend the chosen palette to new scenes. Do not add a new texture every scene.
- Keep scene 1 no louder than the opening. If it grows, ride the gain down only.
- Write a **music direction per scene** in `script.md`, in the user's words, under the scene heading. Quote it back
  when implementing.

## Temp score and SFX (pass A): synthesized, zero large downloads

The animatic needs music and sound effects at once, before any sample library is installed. Synthesize them in Python
(numpy, scipy, soundfile) on the `events.json` clock. If FluidSynth and a small GM soundfont are **already installed**,
you may use them instead for the pitched parts. Do not download anything big for this pass.

The defaults above apply: fixed level, **no ducking**, **no arpeggio filler**, about 10 dB under the voice.

Palette (keep it small, 3-5 sounds):
- **Pad**: 3-4 slightly detuned saws or sines per note, low-passed, slow attack (1-2 s) and release, a chord every
  8-16 s. Sets the mood. Choose a key and a mode from the tone in `brief.md` (warm: major or Lydian, serious: minor).
- **Sub**: a sine an octave or two under the pad root, on section changes only.
- **Swell / riser**: filtered noise with a rising cutoff and level, 2-4 s, ending on an event (the turn, the reveal).
- **Whoosh**: short noise burst with a band sweep (0.3-0.6 s) on scene changes and moves.
- **Click / tick / pop**: a 10-30 ms sine or noise burst with a fast decay, on UI moments (a button, a card landing).
- **Silence**: a dry cut at a dramatic stop, with the reverb tail ringing after (below).

How to build it:
1. A `cues.json` (or a Python list) in the user's project: `{"sfx": "whoosh", "at": "scene2_start"}`,
   `{"pad": "Dm9", "from": "s2_start", "to": "s3_start"}`. Times are **event names** resolved against
   `events.json`. A missing event fails the build.
2. One function per sound returns a float32 array. A mixer places them at their event times. Fade pads over
   their span, and clip every cue to its own time span (a pad cannot outlive its cue).
3. A light shared reverb (a short synthetic impulse response, 2-3 s) on pads and swells. Apply it after the dry cut,
   so silence rings out.
4. Mix: VO + temp score + SFX into `film/public/mix.wav`, 48 kHz stereo float32 internally. Music RMS about 10 dB under
   speech RMS in each span, fixed. Limiter at -1 dBFS on the combined mix. Report RMS ratio, peak, and the first and
   last 500 ms of the file.
5. Deterministic: seeded random, same output for same inputs, cached by hash of (cues, events).

The temp score is allowed to sound like a temp score. It proves timing, level and mood. U3 replaces it.

## One global clock

- The film is one timeline in seconds. The score is one file (or one script producing one MIDI) on that timeline.
  There is no per-scene tempo reset and no per-scene score file with its own zero.
- Rendering is done in **windows** (per scene or act) for memory and speed. Each window renders the same
  score with a **reverb pre-roll** (default 8 s) before its start, then the pre-roll is trimmed. Seams between
  windows are then sample-exact and the reverb tail carries across.
- **Pre-roll leaks:** notes that sound only in the pre-roll must not appear in the window (fade or mute
  the orchestra before the seam, and check the first second of every window for stray notes).
- Every cue limits itself to its own time span. A pad sustaining past its cue span is a bug.

## Cueing to events

Score file (small, human readable, one per film):

```yaml
tempo:                      # piecewise, in bpm; times are event names or seconds-from-event
  - { at: s2_start, bpm: 100 }
  - { at: invoice_sent,  bpm: 100 }
  - { at: freeze,   bpm: 132, land_downbeat: true }
layers:
  pad:      { in: s1_start, out: s2_start, fade_out: 1.5 }
  theme_A:  { in: s2_start, phrase_anchors: { B: invoice_sent } }
  strings:  { in: old_way_end, cc11_ramp: 4.0 }
  silence:  { at: freeze, cut: dry, hall_tail: 3.0 }
```

Rules:

1. **Anchor to the story.** A phrase, a layer entry or a key change attaches to a named event. Never count bars
   from the film start. Reason: when the first act got shorter after retakes, a theme counted from bar 1 shifted
   by half a phrase, and a countermelody landed on the wrong round. It sounded like something had vanished.
2. **Tempo map for landings.** If a downbeat must land on an event (a freeze, a reveal), compute the tempo ramp
   backwards from the event so that beat N falls exactly on it. Use many small tempo events for an
   accelerando. Check that the downbeat is within one video frame (1/60 s).
3. **Layers enter by CC11 (expression) ramps**, not note-on at full level, so they fade in instead of switching on.
   Use CC1 (mod) for brass and string dynamics if the library supports velocity-crossfade.
4. **Phrases:** write the theme as data (notes, durations) in A/B phrases and reuse it. Retakes then change
   only where phrases start, not what they are.
5. **Cuts:** to cut to silence, send all-notes-off at the cut and render **dry**; add reverb afterwards in the mix
   bus so the tail rings out. If reverb is inside the sampler, the cut is audible as a mute.
6. **Resolve cue names at build time** against `events.json`. A missing event fails the build, listing the name.
7. Humanize lightly (a few ms of timing, velocity variation from a seeded RNG). Seeded, so rebuilds are identical.

## Generating MIDI (pass U3)

Use `mido` or `pretty_midi` (Python) or any MIDI library. One track per instrument, one MIDI channel per track.
Write the tempo map as tempo events on track 0. Output `score/film.mid` plus per-instrument stems when rendering.

Convert event seconds to ticks through the **tempo map**, not with a fixed tempo. A helper that maps
`seconds -> beats -> ticks` and back belongs in one place.

## Rendering with samples (pass U3)

- **sfizz**: `sfizz_render --sfz lib/Violins.sfz --midi stem.mid --wav stem.wav --samplerate 48000`. SFZ libraries:
  VSCO-2 Community Edition, Sonatina Symphonic Orchestra, Virtual Playing Orchestra, or the user's own.
- **FluidSynth**: `fluidsynth -ni -F stem.wav -r 48000 lib.sf2 stem.mid`. SF2 libraries are smaller and sound plainer.
- Render **per instrument group** (strings, brass, choir, percussion, pads), each to its own stem, one process at a
  time. Libraries are large (gigabytes) and loading several at once is how memory goes.
- Stems are float32 or 24-bit WAV at 48 kHz. Convert to float32 arrays and accumulate the mix without stacking all
  stems in memory at once.
- Percussion and one-shot SFX can be small CC0 sample sets triggered from events, or synthesized.

## Mix

- Per stem: gentle EQ, then a common **reverb bus** (a convolution or algorithmic hall, 2.5-3.5 s, mix about 30%).
  `pedalboard` (Python) has reverb, compressor, limiter. Any equivalent works.
- Master: fixed gain for the music so its RMS sits about 10 dB under the speech RMS (for example speech
  around -23 dBFS RMS, music around -33). No sidechain.
- Final limiter at -1 dBFS on the **combined** VO + music + SFX. No clipping.
- Stereo: widen pads slightly, keep the bass and the voice centered. Check mono-compatibility by summing to mono
  and comparing levels (a big drop means phase problems). Ask which headphones the user used if they say
  "it sounds mono": spatial-audio modes can fold a stereo mix.

## Measuring without ears

Per scene, report to the user:

- music RMS vs speech RMS in the same span (target about -10 dB)
- peak of the music alone and of the mix
- spectral overlap with speech (energy of the music in 1-4 kHz vs the rest). If the music has a lot there, consider
  moving the theme an octave or thinning the pad.
- onset times of the key musical moments vs the events they should hit (should match to under 20 ms)
- first and last 500 ms of each window (clicks, stray notes)

Then ask the user to listen. Do not say "it sounds great".

## Memory

The score once needed 3 GB before it was rendered in separate processes, with float32 buffers and each cue
confined to its own span. Defaults: one process per window, float32, cues clipped to their span, free stems after
adding them to the mix, and report peak RSS.
